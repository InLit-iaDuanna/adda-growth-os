# G05 ExecPlan — 校园合作、活动执行与推荐核验

## 目标和用户可见结果

提供有来源的组织/KOC 台账、参数化活动模板、报名与现场签到分离、容量事务控制，以及以首次权威订单为条件的推荐奖励待核验台账。系统不生成不存在的人、学校关系、粉丝量或现金支付承诺。

## 仓库现状与依赖

G03 已有来源链接/会员/券/订单事实，G04 已有内容和审批状态。真实校园联系人和活动日程没有提供，模板日期保持未确认/needs_input。

## 设计与文件路径

- `packages/domain/src/campus.ts`：校园合作/活动/推荐合同。
- `packages/db/src/repository.ts`：容量事务、签到唯一性、订单资格和 reward ledger。
- `apps/web/src/server.ts`：partner/event/referral API。
- `tests/g05.test.ts`、`artifacts/G05/`：专项回归和证据。

## 实施步骤

1. partner 建档必须有 source URL/核实时间/联系许可；默认 identified，不自动邀请。
2. 事件模板只提供有限参数化清单；报名不等于签到，重复报名/签到幂等，容量不可超卖。
3. 推荐关系明确 inviter/invitee，首个已导入且退款观察期完成的订单才进入 eligible；自邀、已有历史购买、全额退款排除。
4. reward ledger 只能人工 approve/reverse，不自动支付。
