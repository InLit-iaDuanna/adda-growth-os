# G00 ExecPlan — 基础骨架、权限与可运行环境

## 目标和用户可见结果

交付一个可在无外部服务凭证的本地环境启动的 ADDA Growth OS 基础切片：空生产库首次打开显示资料引导；明确标记的 DEMO 模式可以创建/查看活动；活动写入持久化存储并可在服务重启后读取；每个请求由服务端会话、tenant、store 和角色授权；健康检查、worker 心跳和最小中英文后台壳可观察。

## 仓库现状与依赖

初始仓库只有规格包、合成夹具和 `scripts/verify-fixtures.mjs`，没有应用源码、锁文件或数据库。运行环境提供 Node.js 24 和 npm，未提供 Docker/Postgres；因此 G00 使用文件持久化的本地 repository 作为可执行开发适配器，并将生产 PostgreSQL/Prisma 迁移接口保留为明确的后续适配点，不把本地适配器宣称为生产数据库。

## Surprises & Discoveries

当前运行环境没有 Docker/PostgreSQL，不能诚实地声称完成真实 Prisma/Postgres 迁移或生产部署。先用可替换的本地 repository 让权限和持久化行为可测试，并将生产数据库接入列为 external_blocked。

## Decision Log

- D-G00-01：G00 采用 Node HTTP + TypeScript 的薄 Web/API 适配器，以在当前环境可运行；API/领域边界与固定架构一致，Next.js/Prisma 生产适配器保留后续替换。
- D-G00-02：会话 cookie 使用 HMAC 签名、短期过期和服务端 session 记录；不提供默认生产密码。
- D-G00-03：DEMO seed 通过 `APP_MODE=demo` 显式开启，生产迁移绝不自动注入演示数据。

## 回滚与幂等

所有写入通过 repository 的临时文件 + rename；重复 `db:migrate` 不改变业务数据，重复 seed 使用稳定外部 key 幂等。回滚只需停止服务并恢复上一个 `data/db.json` 备份，不执行递归删除。
