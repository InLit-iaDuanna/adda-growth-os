# G03 ExecPlan — 活动到成交的第一个完整切片

## 目标和用户可见结果

交付一个可演示但明确标记为 DEMO_READY 的第一方闭环：活动生成高熵来源链接，消费者 H5 浏览并注册会员，营销同意独立记录，测试环境可显式验证联系方式；优惠券进入 issued/reservation/pending POS 状态，收银员并发核销只有一个成功，导入权威 POS 订单后才转 redeemed 并产生 primary source 证据。

## 仓库现状与依赖

G00 提供会话/租户/门店权限，G01 提供产品/价格/素材检查，G02 提供 POS staging 和指标引擎。真实验证渠道、POS 凭证和客户同意文案没有提供，生产验证接口返回 external_blocked，不使用假 verified。

- `packages/domain/src/growth.ts`：来源、同意、券和核销状态类型。

- `apps/web/src/server.ts`：公共 H5、来源链接、会员、同意、券和收银 API。

- `artifacts/G03/`：执行证据和已知限制。

## 实施步骤

1. 只存 token hash，公共 URL 不含手机号、姓名或可枚举 member ID。
2. 注册与 marketing opt-in 分开写事件；撤回写 suppression；生产验证无渠道时返回 external_blocked。
3. 券核验在 repository 事务中检查租户、门店、有效期、状态和一次性约束；POS 引用只是 pending，导入支付事实后才 redeem。
4. 核验成功写唯一 verified_coupon evidence，重复匹配不重复归因。
5. 运行专项与全量回归，记录 synthetic/offline 证据。

## Surprises & Discoveries

公共 token 和 coupon token 必须可返回给浏览器一次，但 repository 只保存 HMAC hash；生产部署还需 secure cookie、真实验证服务和隐私告知版本。

## Decision Log

- D-G03-01：触点、报名和扫码不等于到店/支付；只有 POS import + member/order match 才能归因。
- D-G03-02：测试验证码固定仅在 `APP_MODE=test/demo` 可用，生产明确拒绝。

## 回滚与幂等

来源链接、同意和核销事件追加不删除；重复 issue token 返回原券，重复 reservation/match 不改变已完成状态。错误/退款通过状态和审计重述，不盲目重新发放。
