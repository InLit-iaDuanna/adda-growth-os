# 产品规格

## 定位和首版对象

产品名 ADDA Growth OS；面对客户的总控助手可称 ADDA Growth CEO，但 UI 必须说明它是需要人审批的运营助手，不是真实 CEO。首版服务一个品牌一门店、少量运营人员，schema 和权限从第一天保留 tenant 与 store。

角色：OWNER、GROWTH_MANAGER、LOCAL_REVIEWER、STORE_MANAGER、CASHIER、ANALYST。校园 KOC 默认不拥有后台账号，只接收个人协作页和链接，不可查看顾客名单。

## 消费者 H5

路由族：/s/{storeSlug}/c/{opaqueSourceToken}、/join、/member、/events/{slug}、/ref/{opaqueToken}。
提供 English/Bangla 语言切换、品牌和活动事实、可选会员注册、独立营销 opt-in、优惠条款、报名和退出触达。手机首屏不加载后台图表库；资产懒加载。
游客可以浏览活动而不注册。会员联系方式必须经支持的验证流程或授权 POS 的已验证标识导入才能用于触达。开发使用 test outbox，生产没有验证渠道时不伪造已验证状态。
来源 token 使用高熵不透明标识/签名；URL 不放手机号、姓名、顺序会员 ID。公共来源链接只映射活动，不代表店内签到。

## 场景一：内容到门店订单

运营创建活动，指定目标指标、日期、门店、预算上限、有效产品、负责人与规则。系统生成 content brief 后，产出 en/bn 公共文案和 zh-CN 内部说明，保留事实引用。
本地审核员确认 bn；授权人员批准确切版本；发布前验证活动仍有效、素材可用且商品价格未变化。没有平台连接时导出文件与待办。只有上传外部帖子链接并记录人工发布证据后标 manually_published；不能冒充 API 确认。
每个内容变体/渠道/KOC 分配独立来源标识。顾客通过链接加入会员或领取券。收银员输入 POS order_ref 仅建立 pending_pos_verification 关联；真实导入支付记录匹配后才计算营收、首购、来源转化。

## 场景二：校园/KOC 与活动

合作对象来自甲方登记、对方自荐或人工核实的公开商务信息，保存来源 URL、核实时间、联系许可、合作阶段、负责人与交付约定。不得用 AI 编造真人、粉丝量、学校关系或自动扫描私人名单。
KOC 状态：identified → verified → invited → agreed → active → reviewed → paused/closed。只在授权后发邀请；没有权限时生成草稿。
活动类型从参数化模板库选择，首版可提供约 12 种模板，不填充 365 个同质活动。每个模板包含容量、预算、门店负荷、素材许可、日期校验和成功指标；已核实的运动比赛/校园日程才可生成有具体时间的广告。
报名不等于现场到访；现场签到需员工扫描/确认，重复签到去重。未签到不必然未到场，应保留测量限制。
推荐以明确同意的邀请关系和首次观测有效订单核验，排除自邀和重复。奖励先形成待核验台账，达到退款观察期后人工批准，不自动发钱。
UGC 必须记录使用许可范围和有效期；顾客愿意公开发帖不等于品牌可任意二次商用。

## 场景三：轻 CRM 与再消费

保存必要数据：member_id、已验证联系方式/来源、语言、可选学校、注册日期、同意事件、订单行为、可选偏好。默认不收集性别、精确年龄、宗教、收入、好友关系或从照片推断这些属性。
预置规则分群：注册未首购、首购后未二购、14 天未再购、活动参与者、明确 opt-in 的新品兴趣者。规则由代码计算，显示观察数据覆盖范围。禁止将未知历史直接称为真正新顾客。
触达流程：选分群 → 生成候选文案 → 选择批准模板 → 冻结受众与成本 → 审批 → 调度 → 发送前复核 → 回执 → 订单观察。
建议默认每人 7 天最多 1 条营销消息、09:00–21:00 当地时段；这些是可配置产品策略，不是平台法定限额。客服与交易消息另有目的和规则，不应借此绕过营销限制。
支持持久化随机 holdout：分组先于发送；分析保留所有合格已分配成员，不能只比较“已点击/已送达的人”。样本不足显示 exploratory，不给因果提升结论。

## 场景四：评论与客服

V1 提供统一“顾客声音记录+工单”，不假装已覆盖所有私信协议。评论由授权 API、现有客服系统适配器或人工 CSV/文本登记进入。
分类为多标签：产品、甜度、服务、卫生、价格、环境、等待、员工态度、建议、其他。保留原文和证据片段，日汇总区分记录数、去重顾客数与标签数；标签计数不可相加冒充评价总数。
疑似食安、骚扰、人身安全、严重争议立即转人工，模型不诊断、不承诺赔款、不删差评。普通问答只使用已批准品牌事实。已批准回复改变内容后需重新审批。平台不支持回复时创建手工待办。

## 运营阶段

所有计划相对 launch_date 生成；该日期为空则禁止输出具体开业倒计时。
T-21 至 T-8：种子用户、品牌/产品测试和校园合作验证；T-7 至 T+7：受控开业活动、内容与门店承载联动；T+8 至 T+90：首购、二购与会员实验。
200–500 种子用户、KOC 数量和固定增长幅度都只能作为甲方设置的运营目标，不是软件保证。
