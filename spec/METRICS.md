# 指标合同 v1

所有数值由领域服务计算。每个结果返回 metric_key、formula_version、scope、period、value、unit、numerator/denominator（适用时）、as_of、complete_through、coverage、quality、source_refs、missing_reason。
无法测量用 null + reason，不等于零。前期只把真实订单、已核验来源和明确用户同意称为事实。

## 统一定义

C = min(统计截至时间 as_of, 订单源已确认完整的 complete_through)。没有完整性保证的导入仍能展示“已观测数据”，但 cohort 结果标 provisional，不能标观察期完整。
合格订单 Q：真实支付、非测试/取消、截止 C 的退款冲销后净额 > 0 的订单。部分退款仍合格但减额，全额退款不合格；相同 order ID 重导只计一次。fixture 所有金额已统一为净销售口径。
默认顾客分析 store scope，brand scope 仅 OWNER 等授权角色且显式请求后提供。所有表格带 scope 标签。
同日多次购买不作为本产品的“跨日复购”，但订单和销售额正常计入。

## 六个面板

1. 曝光：分别展示平台 impressions/reach/views 的原始定义、时间区间、付费/自然分类和获取方式。不可把 views 当 impressions；可单独展示“跨渠道展示次数之和（未去重）”，不叫独立人数。对可能累计的 lifetime snapshot 取相应最新值或合法差分，不把每日快照相加。
2. 到店：分栏展示“现场核验签到人数”“明确计数方式下的门店客流”“有可核验线上来源的购买人数”。没有门店客流设备或人工计数时总体到店人数=null；扫码、导航点击、报名都不是现场到访。
3. 首单转化：默认清楚命名“新注册会员 7 天内首次观测购买转化率”，而不是全部到店转化。分母为在选择的注册 cohort 内、无可见注册前合格购买且 registered_at + 7d <= C 的成员；分子为该分母中 first Q 位于 [registered_at, registered_at+7d] 的成员。显示已识别、历史覆盖和观察期限制。注册已有老客不放进新客分母。
4. 会员新增：期内新建且去重的 member 数；另列已验证联系数、营销 opt-in 新增数和净变动。注册不等于营销许可，不把重复验证或重导计成新增。
5. 30 天复购：先对每个已识别顾客取首个合格订单 t0；仅 t0+30d <= C 的 first-purchase cohort 进入分母。分子为分母中存在另一个不同订单，且 business_date(t1)>business_date(t0)、t1<=t0+30d。展示分子/分母，不纳入新注册不足观察期顾客。退款可能改变 t0 或复购资格，重算并版本化保存；不覆盖旧报告证据。
6. 老客带新：期内满足已登记推荐关系且被邀请人首次观测 Q 已核验的不同被邀请人数；一人最多归属一个推荐，排除自邀、重复、历史中已购和全额退款。另列“成功推荐者人数”，不能与被邀请人数混称。

## 经营辅助指标

净销售额 = Σ订单统一净销售金额（已扣折扣、不含明确代收税）−Σ净退款。没有税口径时只称 POS 净实收；不同口径不能合并。
客单价 = Q 的净额 / Q 的订单数，分母为 0 返回 null。
身份匹配覆盖率 = 有 member_id 的 Q 数 / 所有 Q 数。
会员销售占比 = member_id 非空 Q 净额 / 所有 Q 净额；与会员订单占比分开。
现金退款日报按实际退款日期记账；活动/cohort 分析按原订单归属并截至 C 重述。两者必须通过调节项对账，不强求任意区间完全一致。

## 归因，不是因果

当前实现模型 `primary_source_v2`：每个 Q 至多一个 primary campaign。优先级：经订单验证的专属券/来源码 > 可连接身份的、订单前 7 天最后一次合格第一方触点 > unknown。
自报“从 TikTok 来”保存在 declared_source 维度，不能自动挤入已验证来源销售。匿名、跨设备和不愿被追踪的人保留 unknown；不使用设备指纹填补。
所有 source evidence 保留关联但不多重累加收入。primary campaign 销售总和 + unknown 必须与总净销售对平；触点、KOC 与活动重叠分析不用于加总总营收。
人工回填来源、公共码传播、码被转发都有偏差，报告明确方法和证据等级。KOC 链接点击不是该 KOC 影响的全部人数。
默认 7 天窗口是产品政策，可配置但变更必须版本化。支持 campaign/content/source_link/partner 分层，默认归因不重分多触点信用。

第三轮修复说明：v2 落实含上下边界的 `[paid_at − 7d, paid_at]` 窗口，输出模型及 `touch_window_days`。当前代码固定七天，配置能力尚未实现。已核验券是订单证据，不套用触点窗口；支付后核验可以进入截至核验时间之后的报告，不进入此前报告。旧 v1 报告保留原记录，需要使用新模型重新计算。

订单身份为 `(tenant_id, store_id, source, external_order_id)`，修订不产生新业务订单。归因写入时绑定明确的内部订单记录和业务来源；旧记录只有外部编号且对应多个来源时不参与主归因。取消、退款、查询期外订单也参与身份歧义检查，不能靠筛除订单猜测来源。

## 回报与实验

可显示“已归因销售 / 已登记活动支出”，但不得将它命名为增量 ROI。
只有订单变动成本、活动费用和优惠处理口径齐全时，计算已归因贡献；POS 实收已扣的优惠不再扣一次。缺 SKU 成本/工时等关键输入时贡献与 ROI 返回 null，展示缺失项。
因果评估只有在预先分配的对照试验、合理执行与足够证据下提供估计及不确定性；低样本报告描述差异，不承诺增量。在 CRM 实验中按分配组统计，包括未送达的人；不可只比较点击者。
